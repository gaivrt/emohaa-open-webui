# 项目架构概览

## 🏗️ 整体架构

Emohaa Open WebUI 基于 Open WebUI 构建，集成了 OpenDify 和 Dify 服务，形成完整的对话AI系统。

```
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│   WebUI 前端    │───►│   WebUI 后端    │───►│    OpenDify     │───►│      Dify       │
│   (Svelte)      │    │   (FastAPI)     │    │   (中间件)      │    │   (AI 服务)     │
└─────────────────┘    └─────────────────┘    └─────────────────┘    └─────────────────┘
        │                       │                       │                       │
        │                       │                       │                       │
    用户交互              身份验证/转发            协议转换/路由           LLM 处理
```

## 🔄 数据流

### 用户对话流程
1. **前端**: 用户输入，发送带有 Chat ID 和 User ID 的请求
2. **WebUI 后端**: 验证用户身份，转发请求到 OpenDify
3. **OpenDify**: 协议转换，会话管理，路由到 Dify
4. **Dify**: LLM 处理，生成回复
5. **返回路径**: Dify → OpenDify → WebUI后端 → 前端

### 身份传递机制
- **Chat ID**: 标识具体的对话会话
- **User ID**: 标识发起对话的用户
- **双重传递**: HTTP头部 + 请求体metadata
- **始终转发**: 不受配置限制的关键信息传递

## 🛠️ 技术栈

### 前端技术
- **Svelte/SvelteKit**: 前端框架
- **TypeScript**: 类型安全
- **Tailwind CSS**: 样式框架
- **Vite**: 构建工具

### 后端技术
- **Python 3.11+**: 主要开发语言
- **FastAPI**: Web框架
- **SQLAlchemy**: ORM
- **SQLite/PostgreSQL**: 数据库
- **Uvicorn**: ASGI服务器

### 基础设施
- **Docker**: 容器化部署
- **Nginx**: 反向代理
- **Redis**: 缓存和会话存储
